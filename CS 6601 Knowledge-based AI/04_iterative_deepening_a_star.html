The idea in one sentence

IDA* keeps A*'s compass, but drops its luggage.

A* uses the admissible heuristic h to expand the most promising stored state. That is usually efficient in node expansions, but every open and closed record consumes RAM. On a cube, the frontier can grow exponentially.

IDA* uses the same score, f = g + h, as a cutoff rather than a global priority. It performs depth-first search, prunes any path over the cutoff, remembers the smallest rejected score, then restarts with that as the next cutoff. It may regenerate states, but its live search structure is only one root-to-leaf path.

A*

Shortest with an admissible heuristic. Usually fewer expansions; exponential frontier memory can be fatal.

IDA*

Also shortest here. Repeats work across thresholds; search memory grows roughly with solution depth.

Greedy best-first

Uses only h. Often darts toward a solution, but a promising-looking detour can make the result longer.

Brute-force BFS

Uses no heuristic. It is shortest for equal-cost moves, but must retain a huge visited set and frontier.

What this lab simplifies: it uses the half-turn metric (18 possible face twists, with consecutive twists of the same face suppressed) and three small abstract pattern databases. Korf's 1997 solver used vastly larger tables. Browser runs are capped deliberately; “capped” means the displayed counts are lower bounds, not estimates of completion.

Why Korf's work mattered

1985 gave search linear space. 1997 gave the cube a practical optimal solver.

The breakthrough was the combination of memory-bounded search and strong precomputed lower bounds.

1985 · IDA*

Korf formalizes the trade-off

Richard E. Korf analyzed iterative-deepening A* as an optimal admissible tree search and demonstrated it on the Fifteen Puzzle. His paper explicitly notes earlier iterative-deepening work and credits Judea Pearl with suggesting its application to A*.

1997 · RUBIK'S CUBE

IDA* meets pattern databases

Korf reported the first optimal solutions to ten random cube instances by combining IDA* with lookup tables that stored exact costs for subsets of cubies.

THE BIG DEAL

Knowledge in RAM, frontier out of RAM

IDA* did not make exponential search disappear. It made memory predictable, leaving scarce RAM available for a stronger heuristic—the pattern database—which removed enormous parts of the search tree.

Primary sources: Korf, Depth-First Iterative-Deepening (1985); Korf, Finding Optimal Solutions to Rubik's Cube Using Pattern Databases (1997).
