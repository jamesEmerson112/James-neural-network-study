# Long-Term Memory Benchmarks: LoCoMo and LongMemEval

The two benchmarks that agent-memory papers (Mem0, A-Mem, MemoryOS, RecMem) report on. Both test whether a system can answer questions about a conversation history that is too long, or too badly organized, to simply paste into the prompt. Companion to [21_llm_benchmarks.md](21_llm_benchmarks.md), which covers general LLM benchmarks.

## LoCoMo (2024)

**Who and why.** Adyasha Maharana and Mohit Bansal at UNC Chapel Hill, Dong-Ho Lee at USC, and Sergey Tulyakov, Francesco Barbieri and Yuwei Fang at Snap Research built it in early 2024 (arXiv 2402.17753). Earlier dialogue datasets covered only a handful of sessions, so nothing tested whether a chatbot could remember a relationship that unfolds over months.

**How it was made.** The conversations are generated by two LLM agents, each given a persona and a timeline of life events, then checked and edited by human annotators. The agents also share images, so the dataset is partly multimodal. Each conversation runs up to 35 sessions and about 300 turns.

**Dataset size discrepancy.** The paper describes 50 conversations averaging about 9K tokens. The public release (`locomo10.json`) contains 10, and memory papers including RecMem describe those 10 as averaging about 16K tokens. Everyone in the Mem0 / A-Mem / RecMem line evaluates on the 10-conversation release.

**Question categories.**

| Category | What it tests |
|---|---|
| Single-hop | One fact from one session |
| Multi-hop | Combining facts from several sessions |
| Temporal | Order of events and relative time ("the week after she moved") |
| Open-domain | Memory plus outside world knowledge |
| Adversarial | False-premise questions; **excluded by convention** because automatic grading of them is unreliable |

**What the original paper found.** Long-context models and RAG helped but still trailed human performance by a wide margin.

## LongMemEval (2024–2025)

**Who and why.** Di Wu and Kai-Wei Chang at UCLA, with Hongwei Wang, Wenhao Yu and Dong Yu at Tencent AI Lab and Yuwei Zhang, released it in October 2024 (arXiv 2410.10813); it appeared at ICLR 2025. LoCoMo is a chat between two people. LongMemEval targets the setting commercial assistants actually face: one user, many separate task-oriented sessions, and an assistant expected to remember across them.

**The "haystack" design.** Each of the 500 questions comes with its own chat history. A few *evidence sessions* contain the answer; the rest are filler sessions, so finding the evidence is a needle-in-a-haystack search.

```
   one LongMemEval question
   ┌──────────────────────────────────────────────────────────┐
   │ filler │ filler │ EVIDENCE │ filler │ ... │ EVIDENCE │ filler │  → question
   └──────────────────────────────────────────────────────────┘
     S variant:  ~30–40 sessions, ~115K tokens
     M variant:  ~500 sessions,   ~1.5M tokens
     Oracle:     evidence sessions only (upper bound)
```

**Five abilities** it tests: information extraction, multi-session reasoning, temporal reasoning, knowledge updates (the user's situation changed; use the newest value), and abstention (say "I don't know" when the history has no answer).

**Question types as reported in memory papers.**

| Type | What it tests |
|---|---|
| Single-session-user | A detail the user said in one session |
| Single-session-assistant | A detail the assistant said in one session |
| Single-session-preference | Using a remembered preference to personalize an answer |
| Multi-session | Combining facts scattered over two or more sessions |
| Knowledge-update | Replacing an outdated fact with a newer one |
| Temporal-reasoning | Dates and order, using session timestamps plus phrases like "last month" |

Abstention questions are mixed into these types rather than forming a separate column.

**Later changes.** The authors cleaned the history sessions in September 2025 to remove filler that interfered with correct answers, so scores on the cleaned and original files are not directly comparable. A follow-up, LongMemEval-V2, appeared in the same repository in May 2026.

## How Memory Papers Run These Benchmarks

```
   ingestion (construction cost)              question time (query cost)
   ─────────────────────────────              ──────────────────────────
   turn 1 ─┐                                   question
   turn 2 ─┼─► memory system builds ──────►   retrieve from memory
   turn 3 ─┤   its stores, one turn            + LLM answers
     ...   ┘   at a time (streaming)           + LLM judge grades it
```

- **Streaming ingestion.** Turns are fed in one at a time, in order, as if the conversation were happening live. The system may not look ahead.
- **Grading.** The main metric is *LLM-as-judge* accuracy: GPT-4o-mini reads the question, the gold answer and the system's answer and marks it correct or not. Token-level F1 is often reported too, but it punishes correct paraphrases: if the gold answer is "16 March, 2023" and the system says "2023-03-16," F1 is near zero.
- **Cost.** Report two token counts separately. *Construction tokens* are spent while ingesting the history (averaged per conversation). *Query tokens* are spent per question. Systems differ wildly on the first and very little on the second.
- **Baselines.** *Full context* pastes the whole history into the prompt. *Naive RAG* splits the history into chunks (RecMem used 2,048-token chunks that never split a message) and retrieves the top few by embedding similarity.

## Reference Numbers (from RecMem, ACL Findings 2026)

All systems use GPT-4.1-mini, with `text-embedding-3-small` for embeddings. Accuracy is LLM-as-judge (%); tokens are in thousands.

**LoCoMo**

| Method | Multi-hop | Temporal | Open-domain | Single-hop | **Overall** | Construct tokens (K) | Query tokens (K) |
|---|---|---|---|---|---|---|---|
| Full context | 82.62 | 79.13 | 57.29 | 90.84 | **84.18** | 0 | 31.52 |
| Naive RAG | 58.87 | 33.96 | 50.00 | 61.24 | 54.42 | 0 | 6.28 |
| MemoryOS | 66.31 | 47.66 | 55.21 | 77.05 | 67.60 | 400.7 | 5.04 |
| Mem0 | 58.16 | 63.86 | 44.79 | 66.23 | 62.92 | 1,520.8 | 2.11 |
| A-Mem | 59.93 | 72.90 | 42.71 | 73.25 | 68.83 | 1,459.9 | 5.56 |
| RecMem | 78.37 | 75.39 | 57.29 | 86.92 | 81.10 | 193.2 | 2.75 |

**LongMemEval-S**

| Method | SS-User | SS-Asst | SS-Pref | Temporal | Knowledge-update | Multi-session | **Overall** | Construct tokens (K) | Query tokens (K) |
|---|---|---|---|---|---|---|---|---|---|
| Full context | 91.43 | 100.00 | 56.67 | 48.12 | 75.64 | 53.38 | 66.20 | 0 | 112.25 |
| Naive RAG | 85.71 | 82.36 | 83.33 | 45.86 | 75.64 | 63.91 | 67.00 | 0 | 11.93 |
| MemoryOS | 94.29 | 89.29 | 100.00 | 54.89 | 80.77 | 67.67 | 74.40 | 669.2 | 9.19 |
| Mem0 | 95.71 | 50.00 | 90.00 | 62.41 | 74.36 | 69.92 | 71.20 | 1,626.5 | 2.00 |
| A-Mem | 95.71 | 100.00 | 63.33 | 52.63 | 82.05 | 61.65 | 71.60 | 1,264.3 | 15.46 |
| RecMem | 95.71 | 96.43 | 86.67 | 68.42 | 75.64 | 65.41 | **76.80** | 365.5 | 5.89 |

**What the two tables show together.** Full context wins on LoCoMo, where the whole history fits comfortably in the prompt, and falls to last place on LongMemEval-S, where it has to read ~112K tokens per question. That fits the "lost in the middle" effect (Liu et al., 2023), and it is why a memory paper should report both benchmarks: LoCoMo alone cannot show that a memory system beats simply using a long context window.

RecMem's headline saving on LoCoMo is

$$1 - \frac{193.2}{1520.8} \approx 0.873,$$

an 87% cut in construction tokens relative to Mem0.

## Pitfalls When Using Them

- **Exclude LoCoMo's adversarial category** if you want to compare with published numbers; nearly every memory paper does.
- **Check which LongMemEval file you use.** The September 2025 cleaned version changes scores.
- **Match the judge.** Published LoCoMo numbers use a GPT-4o-mini judge with a prompt adapted from MemGPT; LongMemEval has an official judge prompt. A different judge or prompt shifts scores by several points.
- **LoCoMo's license is non-commercial** (CC BY-NC 4.0).
- **Small LoCoMo means noisy results.** With 10 conversations, a few points of difference between systems may not be meaningful; RecMem averaged three runs.
